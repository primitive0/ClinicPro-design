# ADR 2026-11.1 &mdash; Выбор технологии программирования серверной части

**Статус:** Принято   
**Дата:** 2026-11-12

## Контекст

В ADR-001 для ClinicPro выбрана микросервисная архитектура. Серверная часть должна обрабатывать запросы пользователей, обеспечивать работу с расписанием и медицинскими картами, выполнять фоновые задачи и взаимодействовать с внешними информационными системами.

При выборе языка программирования необходимо учитывать следующие требования:

- **PER01–PER03, SCA01–SCA04:** высокая производительность и возможность обслуживать растущую нагрузку.
- **AVA01, DUR01:** надёжная работа сервисов и возможность их независимого восстановления.
- **SEC01, SEC05–SEC08, PRN01:** безопасная обработка медицинских данных и минимизация ошибок, связанных с управлением памятью и конкурентным доступом.
- **MON01–MON02:** поддержка инструментов мониторинга, журналирования и трассировки.
- **LIM01, LIM05–LIM06:** возможность развёртывания и обновления серверных компонентов в инфраструктуре медицинского учреждения.

Также важны простота разработки и сопровождения большого количества микросервисов, наличие развитой экосистемы библиотек и инструментов, а также удобство реализации сетевых приложений.

## Обсуждение

### Go

Go — компилируемый язык программирования со статической типизацией, автоматическим управлением памятью и встроенными средствами конкурентного программирования.

Для разработки серверной части ClinicPro Go обладает следующими преимуществами:

- **Простота языка.** Go имеет сравнительно небольшой набор языковых конструкций и придерживается единообразного подхода к разработке. Это упрощает чтение и сопровождение кода, особенно при работе нескольких команд над разными сервисами.
- **Конкурентное программирование.** Горутины позволяют создавать большое количество относительно легковесных конкурентных задач. Это удобно для сетевых сервисов, одновременно обрабатывающих множество запросов и обращений к внешним системам.
- **Развёртывание.** Go позволяет компилировать приложения в самостоятельные исполняемые файлы, не требующие отдельной языковой виртуальной машины. Это упрощает поставку и обновление микросервисов в инфраструктуре медицинских учреждений.
- **Инструменты разработки.** Go предоставляет стандартные инструменты для сборки, управления зависимостями, форматирования, тестирования, профилирования и обнаружения гонок данных. Это позволяет использовать единый процесс разработки для всех сервисов.
- **Стандартная библиотека.** Go включает развитые средства для работы с сетью, HTTP, криптографией и сериализацией данных, что позволяет реализовать значительную часть инфраструктурной логики серверных приложений без сторонних библиотек.
- **Большой пул разработчиков.** На рынке труда имеется большое число специалистов, умеющих вести разработку на Go.

При этом Go имеет следующие недостатки:

- **Ограниченная выразительность системы типов.** По сравнению с Java Go предоставляет меньше возможностей для моделирования сложных типов и ограничений. В частности, в Go отсутствуют прямые аналоги некоторых средств Java, таких как иерархии запечатанных типов (`sealed`) и проверка полноты сопоставления с образцом.
- **Сборщик мусора.** Автоматическое управление памятью создаёт дополнительные накладные расходы и может влиять на задержки выполнения.
- **Примитивность.** Go был спроектирован как примитивный язык. В нём встречается больше бойлерплейта, а некоторые решения в нём нелаконичны.
- **Специализированные библиотеки.** Экосистема Go может уступать Java и .NET по зрелости библиотек для отдельных корпоративных и медицинских интеграций.

### Java/Kotlin

Java и Kotlin предоставляют зрелую экосистему серверной разработки, развитые инструменты мониторинга, профилирования и множество библиотек для интеграции с корпоративными информационными системами.

Java обладает более выразительной системой типов, а Kotlin дополнительно предоставляет средства, позволяющие писать более компактный код. Современная JVM поддерживает виртуальные потоки, благодаря которым разработка высококонкурентных сетевых приложений стала значительно проще.

Основным недостатком Java/Kotlin по сравнению с Go является более сложная среда выполнения и конфигурация JVM. Кроме того, экосистема предоставляет множество инструментов и подходов, что может увеличивать сложность технологического стека.

### C#/.NET

C# и платформа .NET предоставляют развитые средства разработки серверных приложений, эффективную асинхронную обработку запросов, инструменты диагностики и широкую поддержку различных платформ. C# также обладает более выразительной системой типов и более широким набором языковых возможностей, чем Go.

Основной недостаток .NET для ClinicPro связан с особенностями экосистемы Microsoft и её положением на российском рынке. Несмотря на открытость и кроссплатформенность современного .NET, часть корпоративных библиотек, инструментов и интеграционных решений по-прежнему ориентирована на технологии Microsoft, такие как Windows Server, IIS и SQL Server.

Дополнительным фактором являются ограничения доступности коммерческих продуктов, технической поддержки и других сервисов Microsoft в России. Для ClinicPro, развёртываемой непосредственно в инфраструктуре медицинских учреждений, желательно минимизировать подобные зависимости.

Хотя использование .NET не требует привязки к инфраструктуре Microsoft, Go предпочтительнее с точки зрения простоты технологического стека и независимости стандартных инструментов разработки и развёртывания от конкретного поставщика.

### TypeScript/Node.js

Node.js позволяет разрабатывать серверные приложения на TypeScript, используя развитую экосистему библиотек для веб-разработки. К преимуществам относятся удобство асинхронного программирования и возможность использовать один язык на клиентской и серверной сторонах.

Однако для ClinicPro данная технология имеет существенные недостатки:

- **Производительность.** JavaScript уступает компилируемым языкам, таким как Go, в ряде вычислительно интенсивных задач. Кроме того, однопоточная модель выполнения JavaScript требует использования дополнительных механизмов для параллельной обработки таких задач. Это усложняет эффективное использование многоядерных систем.
- **Система типов.** TypeScript предоставляет статическую проверку типов, однако его система типов намеренно допускает небезопасные конструкции, включая `any` и приведения типов без проверки во время выполнения. Это ограничивает возможность обнаружения ошибок на этапе компиляции и требует дополнительных проверок данных, особенно при работе с внешними API.
- **Потребление ресурсов.** Среда выполнения Node.js и JIT-компиляция создают дополнительные накладные расходы на память и запуск приложений, что может быть нежелательно при развёртывании большого количества микросервисов.

Для ClinicPro преимущества TypeScript/Node.js не компенсируют перечисленные недостатки.

### Rust

Rust обеспечивает высокую производительность, эффективное использование ресурсов и безопасность памяти без сборщика мусора. Его система типов и механизм владения позволяют обнаруживать многие ошибки управления памятью и конкурентного доступа на этапе компиляции.

Однако более сложная модель программирования повышает требования к разработчикам и может увеличивать трудоёмкость реализации прикладной бизнес-логики.

Для ClinicPro строгие гарантии Rust представляют интерес, но в типичных серверных приложениях преимущества низкоуровневого контроля над памятью могут не оправдывать дополнительную сложность разработки.

## Решение

**Использовать Go в качестве основного языка программирования серверной части ClinicPro.**

Все прикладные микросервисы, включая обработку пользовательских запросов, бизнес-логику, фоновые задачи и адаптеры внешних интеграций, разрабатываются на Go.

Выбор обусловлен сочетанием производительности, встроенных средств конкурентного программирования, простоты разработки и удобства развёртывания независимых сервисов.

Решение не распространяется на клиентскую часть, системы управления базами данных и сторонние инфраструктурные компоненты. Конкретные фреймворки, протоколы взаимодействия и технологии хранения данных определяются отдельными архитектурными решениями.
