# ADR 2026-11.3 &mdash; Выбор технологии программирования клиентского приложения

**Статус:** Принято  
**Дата:** 2026-11-12

## Контекст

ClinicPro предоставляет веб-интерфейс для пациентов, врачей и административного персонала. Пользователи работают с расписанием, записью на приём, медицинскими документами и другими функциями системы. Клиентская часть взаимодействует с серверными сервисами через API.

При выборе технологии разработки интерфейса необходимо учитывать следующие требования:

- **PLT01–PLT03:** работа в поддерживаемых браузерах на настольных и мобильных устройствах, адаптивность интерфейса и отсутствие необходимости устанавливать отдельное приложение.
- **ACC01–ACC04:** соответствие публичных страниц и личного кабинета пациента WCAG 2.2 AA, поддержка скринридеров, клавиатурного управления и режима для слабовидящих.
- **L10N01–L10N02:** поддержка русского и английского языков и возможность добавления новых локализаций.
- **PRN06:** поддержка различий между учреждениями и странами без дублирования основной логики системы.

Интерфейс содержит множество интерактивных элементов: формы, расписания, таблицы и представления медицинских данных. Для его развития необходимы повторное использование компонентов, удобное управление состоянием и возможность параллельной работы разработчиков над отдельными функциональными областями.

Учитывая предполагаемый объём клиентского кода, также необходимо обеспечить статическую проверку типов для обнаружения ошибок на этапе разработки и упрощения сопровождения приложения.

## Обсуждение

### React

React — библиотека для создания пользовательских интерфейсов на основе декларативных компонентов.

Для разработки клиентской части ClinicPro React обладает следующими преимуществами:

- **Экосистема.** React имеет обширную экосистему библиотек и инструментов, включая решения для сложных таблиц, форм, маршрутизации, управления серверными данными и построения доступных пользовательских интерфейсов. Это позволяет использовать готовые компоненты для реализации функциональности ClinicPro.
- **Гибкость архитектуры.** React не навязывает единую структуру приложения, конкретный маршрутизатор или способ управления состоянием. Это позволяет выбирать инструменты в зависимости от потребностей проекта и организовать клиентскую часть по функциональным областям.
- **Распространённость.** React широко используется в промышленной веб-разработке, что облегчает поиск разработчиков, технической документации и решений типовых проблем.
- **Инструменты разработки.** React поддерживается современными инструментами сборки, тестирования и отладки. Его экосистема позволяет организовать автоматизированное тестирование компонентов и пользовательских сценариев.
- **Возможность разработки мобильных приложений.** React Native позволяет создавать приложения для Android и iOS с использованием React. При необходимости разработки отдельных мобильных клиентов ClinicPro можно будет повторно использовать часть бизнес-логики, средств взаимодействия с API и опыта разработчиков. При этом компоненты веб-интерфейса не являются автоматически совместимыми с React Native.
- **Поддержка TypeScript.** React обладает развитой поддержкой TypeScript, позволяющего выполнять статическую проверку типов компонентов, их свойств, состояния и прикладной логики. Для ClinicPro это особенно важно ввиду большого объёма клиентского кода: проверка типов помогает обнаруживать ошибки до выполнения приложения, упрощает рефакторинг и обеспечивает соблюдение контрактов между модулями.

При этом React обладает следующими недостатками:

- **Необходимость выбора дополнительных библиотек.** React отвечает прежде всего за построение интерфейса. Для маршрутизации, работы с серверными данными и других задач требуется отдельно выбирать инструменты и обеспечивать их совместимость.
- **Управление состоянием.** При неправильной организации компонентов и состояния могут возникать избыточные обновления интерфейса, усложняться передача данных и сопровождение приложения.
- **Изменчивость экосистемы.** Разнообразие сторонних решений и подходов к организации приложений усложняет выбор технологий и требует поддержания единых архитектурных соглашений.

### Vue

Vue — фреймворк для создания пользовательских интерфейсов, предоставляющий реактивную систему обновления данных и компонентную модель разработки.

К преимуществам Vue относятся относительно низкий порог освоения, удобная работа с реактивным состоянием и наличие официальных решений для маршрутизации и управления состоянием. Использование однофайловых компонентов позволяет объединять разметку, логику и стили в структурированном виде.

Vue способен удовлетворить функциональные и нефункциональные требования ClinicPro. Однако React предпочтительнее благодаря более широкому выбору сторонних решений, особенно для сложных интерактивных интерфейсов, и большей распространённости в промышленной разработке.

При этом преимущество React не является принципиальным: Vue также располагает зрелой экосистемой и позволяет реализовать аналогичную архитектуру приложения.

### Angular

Angular — комплексный фреймворк для разработки веб-приложений, предоставляющий встроенные средства маршрутизации, внедрения зависимостей, работы с формами и организации приложения.

К преимуществам Angular относятся единообразная архитектура, развитая интеграция с TypeScript и наличие стандартных инструментов для решения типовых задач. Это особенно полезно при разработке крупных приложений несколькими командами.

Однако Angular предполагает использование более сложной архитектурной модели и значительного набора собственных механизмов. Для ClinicPro это создаёт дополнительные требования к освоению фреймворка и ограничивает свободу выбора отдельных технологических решений.

## Решение

**Использовать React и TypeScript для разработки клиентской части ClinicPro.**

Выбор React обусловлен развитой экосистемой, широким выбором библиотек для сложных интерактивных интерфейсов, распространённостью технологии, гибкостью архитектурных решений и возможностью использования React Native для разработки мобильных клиентов в будущем.

TypeScript выбран для обеспечения статической проверки типов в большом объёме клиентского кода, снижения вероятности ошибок и упрощения сопровождения приложения. Для проекта необходимо использовать строгий режим проверки типов (`strict`). При этом данные, поступающие из внешних источников, должны проверяться во время выполнения, поскольку TypeScript не обеспечивает такой проверки автоматически.

На React с использованием TypeScript будут реализованы пользовательские интерфейсы пациентов, врачей и административного персонала с взаимодействием с серверной частью через API.

Выбор React не означает обязательной разработки отдельных мобильных приложений на React Native. Такая необходимость и соответствующее технологическое решение рассматриваются отдельно.
